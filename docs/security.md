# Viora Security & Privacy Policy

## Security Model Overview
Viora adheres to a zero-trust architecture across all client and backend operations:

1. **No Client Balance Manipulation:**
   - Client applications never write directly to `coin_wallets` or balance tables.
   - All coin deductions, diamond credits, and withdrawal requests execute through atomic Supabase PostgreSQL transactions or signed Edge Functions.

2. **Agora Token Security:**
   - Agora App Certificates are never bundled inside the client application or APK.
   - Tokens are issued with a strict 2-hour TTL (`privilegeExpiredTs`) validated against user authentication headers.

3. **Row Level Security (RLS):**
   - Every user-facing database table has RLS enabled.
   - Users can only read and modify their own authorized records.
   - Moderator and Admin routes require database verification of `profiles.role` claims.

4. **Idempotency Protection:**
   - Financial transactions require an `idempotency_key` (UUID v4) generated by the client prior to dispatch.
   - Repeated submissions with the same key return the existing record without double-charging.

5. **Secrets Management:**
   - Real keys and certificates are injected solely through environment variables (`.env`) or cloud provider secrets vaults.
